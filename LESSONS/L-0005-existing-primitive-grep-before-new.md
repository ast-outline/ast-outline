Правило: прежде чем объявить в `cli.py` новый модульный хелпер или константу-набор, грепни по `src/ast_outline/` не (только) предполагаемое ИМЯ, а СОДЕРЖИМОЕ: для набора kind'ов — любой его элемент (`grep -rn "KIND_STRUCT" src/`), для хелпера — характерную операцию тела (`commonpath`, `os.path.relpath`). Нашёлся примитив с тем же содержимым — импортируй его (при нужде расширь на месте определения), а не заводи локальный синоним. Отдельный признак промаха прямо в diff: если новое объявление тянет импорт нескольких мелких констант, из которых уже собран готовый агрегат, — ты пишешь синоним.

Почему: механизм промаха — поиск существующего идёт по имени того понятия, которым его назвал ты, а в проекте оно названо иначе (`_CTOR_OWNER_KINDS` vs `TYPE_KINDS`) либо лежит в модуле, куда не подумал заглянуть (`json_output`, а не `core`). Совпадает ровно СОДЕРЖИМОЕ, не имя, поэтому name-grep даёт пусто и подтверждает ложную уверенность «такого нет». Дубль тихий: тесты зелёные, поведение верное, цена — расходящиеся во времени копии одного понятия (набор kind'ов пополнится в `core.py`, а `cli.py` продолжит судить по старому). Оба хита словили только ревью-агенты, второй — два независимо; ни один не поймали тесты и не поймал исполнитель.
